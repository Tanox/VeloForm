# 2026-08-09

## 项目审查与修复（Veloform v4.4.0 → v4.4.1）

完成对 Veloform 项目的系统性审查与修复，提交目标：main 分支（当前已在其上）。

### 关键发现与修复
1. **BOM 阻塞构建**：`package.json`、`src/app/globals.css`、`src/middleware.ts`、`src/lib/constants/app.ts`、`src/lib/storage.ts`、`README.md` 含 UTF-8 BOM，导致 `next build` 的 webpack JSON 解析失败（`Unexpected token`）。已用脚本移除全部 BOM。
2. **外部字体网络依赖**：`src/app/layout.tsx` 使用 `next/font/google`（Fraunces/Hanken Grotesk），构建时强依赖 fonts.gstatic.com，离线/CI 失败。改为由 `globals.css` 的 `--font-display`/`--font-sans` 系统字体栈（SF Pro）提供，**对齐 prototype/design-system-spec.md「无需网络加载，原生支持」**要求。
3. **测试框架无法运行**：vitest 1.2 与 Node 26 不兼容（`run` 不执行测试）。升级 `vitest`/`@vitest/coverage-v8` 至 ^3.2.0（实测 3.2.7 安装成功），`vitest.config.ts` 的 `pool` 由 `'forks'` 改为 `'threads'`（Windows 兼容）。
4. **2 个测试文件 mock/require 缺陷**（非代码 bug，是测试本身问题）：
   - `src/lib/storage.test.ts`：用动态 `require('./storage')`，vitest 3 ESM 下 `require` 不支持解析 .ts → 改为顶部静态 import。
   - `src/lib/supabase-service.test.ts`：mock 的 query builder 方法不返回可链式对象，且 `getSupabaseClient` 未用 `vi.fn()` 包装 → 重写 mock 为 thenable builder + `vi.fn()` 包装 client 工厂。
5. **性能**：`src/lib/shareable-config.ts` 的 `encodeBase64Utf8` 逐字节拼接改为分块 `String.fromCharCode(...chunk)`，降低大配置编码开销。
6. **安全注释**：`BikeTypeSelector`/`BuildListItem` 的 `dangerouslySetInnerHTML`（静态 SVG 图标）补充信任来源注释。

### 审查结论（无高危）
- 无硬编码密钥、无 SQL 注入、无 eval/new Function。
- i18n 完整对齐：`satisfies Translations` 编译期保证 en/zh-CN 键一致，多语言切换机制正常。
- 无 src 文件超 200 行（最长 Hero.tsx 198 行），无需拆分。
- RLS：supabase 迁移已收紧 configurations 仅所有者可读写，无 IDOR。
